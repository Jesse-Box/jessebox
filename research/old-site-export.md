## 1. URLs the current site serves

### Canonical host and redirects (live, via `curl -w %{redirect_url}`)

Host: Netlify (`server: Netlify`, `cache-status: "Netlify Edge"`), HSTS `max-age=31536000`.

| Request | Response |
| --- | --- |
| `http://jessebox.net` | 301 → `https://jessebox.net/` |
| `https://jessebox.net` | 301 → `https://www.jessebox.net/` |
| `http://www.jessebox.net` | 301 → `https://www.jessebox.net/` |
| `https://jessebox.net/about` | 301 → `https://www.jessebox.net/about` |
| `https://www.jessebox.net/about` | 301 → `https://www.jessebox.net/about/` |
| `https://www.jessebox.net/<post-slug>` | 301 → `https://www.jessebox.net/<post-slug>/` |
| `https://www.jessebox.net/404/` | 301 → `/404` |
| unknown path (e.g. `/nope`) | 404 |

So **`https://www.jessebox.net` is canonical**; apex and http redirect to it, and Netlify adds a trailing slash to page paths. There is no `netlify.toml` or `static/_redirects` in the repo — these redirects come from Netlify's domain settings and its default "pretty URLs" handling, not from code.

### URL patterns in the code

- `gatsby-node.js`: one page per `allDatoCmsPost` record at `path: post.node.slug` — i.e. posts live at the **root**, `/<slug>`, no `/blog/` prefix or date. Template `src/templates/blog-post.tsx`.
- `src/pages/`: `index.tsx` → `/`, `about.tsx` → `/about/`, `404.tsx` → `/404` (Netlify's 404 page).
- `gatsby-config.js`: `siteUrl: https://www.jessebox.net/`.

### Content models used (from the GraphQL queries)

- **`post`**: `slug`, `title`, `date`, `seo { description, image }`, `seoMetaTags`, `hero` (image: `alt`, `title`), `body` — modular content of two block types:
  - `text` — a Markdown text field (`textNode.childMarkdownRemark.html`, so it is stored as Markdown and rendered by `gatsby-transformer-remark`; embedded videos via `gatsby-remark-embed-video`).
  - `visual` — `media` image with `alt` and `title` (used as caption).
- **`home`** (singleton): `header`, `subheader` (Markdown), `linkTo`, `linkLabel`, SEO.
- **`about`** (singleton): `hero`, `header`, `subheader` (Markdown), `body` (same `text`/`visual` blocks), SEO.
- **`not_found`** (singleton) for the 404 page; `site` global SEO (`siteName`).

### Assets

- **Content images** are not on jessebox.net; they are served from DatoCMS's CDN: `https://www.datocms-assets.com/33198/<timestamp>-<filename>` (project/site id `33198`), with imgix query params for responsive `srcset`s. Example: `https://www.datocms-assets.com/33198/1618494371-diagram-tokensused.png`. The "growing a design system" post alone references 10+ distinct assets. These URLs disappear if the DatoCMS project is deleted.
- **Self-hosted** (in `static/`, served from the site root): `/favicon_16x16.ico`, `/fonts/GT-Alpina-Standard-Regular.woff(2)`, `/fonts/GT-Flexa-Expanded-Bold.woff(2)`, `/fonts/GT-Flexa-Standard-Regular.woff(2)`, `/robots.txt`.
- **Gatsby build output**: hashed `/app-*.js`, `/framework-*.js`, `/styles.*.css`, `/component---*.js`, and `/page-data/<path>/page-data.json` (e.g. `/page-data/index/page-data.json` → 200). These are build artefacts, not linkable content.

### Side observation

The served HTML has no `<title>`, `og:*`, or canonical tags in the static markup — `HelmetDatoCms` is used but `gatsby-plugin-react-helmet` is not in `gatsby-config.js`, so SEO tags are only added client-side (if at all). The SEO data does exist in `page-data.json` (`seoMetaTags`).

## 2. Exporting content and media out of DatoCMS

The overview of official options is the DatoCMS page [Available Export & Backup Options](https://www.datocms.com/docs/import-and-export/export-data). It says all content is reachable through the APIs, and lists: Marketplace plugins (Project Exporter, Export To Google Docs), a custom script against the REST Content Management API, and an Enterprise-only managed export.

### Option A — Project Exporter plugin (official, no code)

[datocms-plugin-project-exporter](https://www.datocms.com/marketplace/plugins/i/datocms-plugin-project-exporter) is an official plugin run from the dashboard:

- Install it, let it use the current user's API token, then Configuration → Plugins → Project Exporter.
- "Download all records" as **JSON**, CSV, XML or XLSX. JSON holds the records as the CMA returns them, **with nested blocks**, plus `schema`, `projectConfiguration` and a `referenceIndex` of every link/asset/block reference.
- "Download all assets" makes ZIP files (up to 150 MiB / 100 files each), with files named `u_<uploadId>__<filename>` and a `manifest.json` that maps each file to its upload ID, filename and metadata.
- Requires: admin login to the DatoCMS project. You don't need to manage an API token yourself.
- Output is JSON, not Markdown. Converting to Markdown files is a separate step.

### Option B — Custom script against the Content Management API (CMA)

- The [export docs](https://www.datocms.com/docs/import-and-export/export-data) give two template scripts using `@datocms/cma-client-node`:
  1. `client.items.listPagedIterator({ nested: true, filter: { type: modelIds } })` dumps every record (with blocks inline) to JSON.
  2. `client.uploads.listPagedIterator()` and download `https://<site.imgix_host><upload.path>` for each upload.
- [List all records](https://www.datocms.com/docs/content-management-api/resources/item/instances): `GET /items`, paginated (max 500 per page). `nested=true` returns full block content instead of block IDs. `version=published|current` chooses published or latest draft.
- [List all uploads](https://www.datocms.com/docs/content-management-api/resources/upload/instances?language=http): `GET https://site-api.datocms.com/uploads`, paginated, with each upload's metadata (filename, alt/title, etc. per the [Upload resource](https://www.datocms.com/docs/content-management-api/resources/upload)).
- **Token**: [CMA authentication](https://www.datocms.com/docs/content-management-api/authentication) — create/use a token in Project Settings → API Tokens with "Access the Content Management API" enabled; send as `Authorization: Bearer <token>`, `X-Api-Version: 3`. The docs' sample uses a "full-access" key. The export calls only read data, so a token with a read-only role may be enough, but that is unverified.
- Markdown: the post `body.text` blocks and `subheader` fields are stored as Markdown (inferred from the Gatsby pipeline using `childMarkdownRemark`), so the CMA should return the raw Markdown strings. A script would write a front-matter + Markdown file per post. It would need to turn `visual` blocks into image references and download hero/visual assets next to them.

### Option C — Content Delivery API (GraphQL, read-only)

- [CDA authentication](https://www.datocms.com/docs/content-delivery-api/authentication): every project has default read-only tokens "CDA Only (Published)" and "CDA Only (Draft)" under Settings → API tokens.
- You can query `allPosts`, `allUploads` (with `url`, `alt`, `title`, etc. — see [Images and videos](https://www.datocms.com/docs/content-delivery-api/images-and-videos)) and the singletons. Then download asset URLs.
- The existing `DATO_CMS_TOKEN` used by `gatsby-source-datocms` is described in the plugin's [README](https://github.com/datocms/gatsby-source-datocms) as a read-only token ("Make sure to grant both CDA and CMA permissions"), so the same token may also work for Options B/C. That is not verified here; the token is not in the repo.

### Option D — Enterprise Project Exports

[Enterprise Project Exports](https://www.datocms.com/docs/import-and-export/datocms-site-export-feature) sends scheduled JSON snapshots and asset files to the customer's own S3 bucket, set up through support. It is **Enterprise-only**, so it doesn't apply to a personal project.

### Option E — no-credentials fallback (from the live site)

The live site already exposes everything that is published: the rendered HTML of each post in `/page-data/<slug>/page-data.json` (body HTML, titles, dates, SEO description, image alt/title) and the images at public `datocms-assets.com` URLs. This would give **HTML** (converted from the original Markdown), not the source Markdown. It only covers content that is published and linked. It needs no token.

### Scale

There are 3 posts plus home/about/404 singletons. A few dozen images at most (≈13 asset references on the largest post).
